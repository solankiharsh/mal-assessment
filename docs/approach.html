Ledger Core — Thought Process & Approach

Artifact date: 2026-09-18. This visual summarizes implementation choices, constraints, and production trade-offs.

Problem Frame

Non-negotiables first

  • Append-only postings; no mutation/deletion of prior records.
  • Stream order governs decisions and validation outcomes.
  • Value date governs effective closes and historical monetary effects.
  • Interest accrues daily and capitalizes once at end of Day 6.
Modeling

Single replay seam

  • replay_ledger(accounts, events) is the public seam.
  • Internal helpers remain private.
  • Tests assert literal outputs, not helper internals.
Critical Fix

Closed-day fee timing

  • Overdraft fee assessment waits for day close.
  • Backdated postings can trigger fees on already closed historical days.
  • Open current day is never fee-assessed mid-day.
Precision

Currency-safe arithmetic

  • AED 2dp, BHD 3dp using Decimal.
  • E10 conserves exact BHD total as 3.333, 3.333, 3.334.
  • Daily rounded interest accruals sum exactly to capitalization.
Incremental Build Flow
1) Spec pass → constants, ambiguities, and rejected criteria captured first.
2) Core pass → append-only replay + authorization + settlement + reversal + fees + interest.
3) Evidence pass → literal invariant tests for E6, E7/E9, ACC-002 interest, and checkpoints.
4) Delivery pass → CI, architecture writeup, HTML artifact, and PDF submission file.

Production Architecture & Trade-offs

Append-only at scale
  • Hot path: close_for_day() repeatedly scans postings.
  • At 100× volume, CPU/read amplification likely hurts before append throughput.
  • Cheapest improvement: keep immutable journal + add derived per-account/day close index + optional checkpoints outside debug/test mode.
Value-dated in production
  • Two time axes: booking-time decisions and value-date monetary effects.
  • Backvalued entries can alter historical closes, fees, and customer-facing outputs.
  • Proposed control: Backvalue Impact Gate with reason, provenance, impact diff, and maker-checker for material customer-visible changes.
Authorization lifecycle

IMPLEMENTED

  • Only non-settlement terminal outcome: DECLINED.
  • ACTIVE may remain open within the exercise window.
  • Unknown/inactive settlement reference is an error, not a lifecycle transition.

NOT IMPLEMENTED / PRODUCTION GAP

  • EXPIRED
  • VOIDED / authorization reversal
  • PARTIALLY_CAPTURED with remainder release
  • ADMIN_RELEASED / NETWORK_RELEASED
