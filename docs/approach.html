Ledger Core — Thought Process & Approach

Artifact date: 2026-09-18. This visual summarizes incremental engineering decisions, tradeoffs, and verification strategy.

Problem Frame

Non-negotiables first

  • Append-only ledger; no mutation/deletion.
  • Stream order drives decisions; value date drives closes.
  • Overdraft fee is AED-only in this fixture (no FX rule provided).
  • Interest accrues daily on positive close; capitalizes once on Day 6.
Modeling

Single replay seam

  • replay_ledger(accounts, events) returns full report.
  • Internals hide postings, fee reconciliation, auth state machine.
  • Tests bind to externally visible outcomes, not private helpers.
Risky Edge

Backdated debit cascade

  • E7 (booked Day 5, value Day 2) changes historical closes.
  • Fee reconciliation runs chronologically Day 1..current booked day.
  • Result: fees on Day 2, Day 4, Day 5 exactly once each.
Precision

Currency-safe math

  • Use Decimal with per-currency quantization.
  • AED 2dp, BHD 3dp.
  • E10 split conserves total as 3.333, 3.333, 3.334.
Incremental Build Flow
1) Spec pass → captured constants, ambiguities, rejected criteria before code.
2) Core pass → implemented append-only postings + auth/settlement/reversal + fees + interest.
3) Verification pass → golden tests + deterministic replay test + known-red intentional failure.
4) Delivery pass → README runbook + CI workflow + PR description artifact.
Acceptance Readout
  • ✔ Runnable replay command prints per-day balances, fees, auth states, and errors.
  • ✔ Required docs present: README, NUMBERS, AMBIGUITIES, REJECTED, WORKLOG.
  • ✔ One intentionally failing test included and annotated.
  • ⚠ Known-red test intentionally fails by design; CI excludes it from pass gate.
  • ✘ No web/UI/database/persistence layer added (as required).
